💾 Week 2 — Database & Storage Foundation (AWS) · L100

Bản tóm tắt súc tích, dễ áp dụng ngay. Giữ “form” như Network Foundation, bổ sung phần quiz tương tác ở cuối.

AWSDatabaseStorage RDSDynamoDBRedshiftS3

Tuần 2 tập trung vào cơ sở dữ liệu và lưu trữ trong hệ sinh thái AWS. Mục tiêu là nắm nguyên tắc thiết kế (mô hình dữ liệu, HA/DR, bảo mật, tối ưu hiệu năng/chi phí) và cách chọn dịch vụ đúng việc giữa RDS, DynamoDB, Redshift, S3/EBS/EFS/FSx…

TL;DR — 10 điểm chốt

  • ✅ Chọn mô hình dữ liệu: quan hệ (OLTP), NoSQL (key‑value/document/graph), kho dữ liệu (OLAP).
  • ✅ Chọn dịch vụ đúng việc: RDS/Aurora (relational), DynamoDB (NoSQL), Redshift (DW), Neptune (graph), ElastiCache/MemoryDB (in‑memory), QLDB (ledger).
  • ✅ S3 storage classes: Standard / Intelligent‑Tiering / *Glacier* (FR/IR/DR) — tối ưu theo tần suất truy cập.
  • ✅ EBS: gp3 (provision IOPS/throughput), io2 (IOPS cao), st1/sc1 (HDD cho tuần tự/lạnh).
  • ✅ EFS: NFS đa AZ, đọc thấp tới ~250 µs, scale‑out theo nhu cầu.
  • ✅ HA/DR: Multi‑AZ (RDS/EFS/DynamoDB), snapshot/backup, cross‑Region khi cần RTO/RPO chặt.
  • ✅ Bảo mật: mã hóa at‑rest/in‑transit, IAM least‑privilege, KMS keys, audit bằng CloudTrail.
  • ✅ Hiệu năng: cache (DAX/ElastiCache), index/partition, auto‑scaling, cấu hình IOPS/throughput hợp lý.
  • ✅ Chi phí: chọn lớp S3 đúng, lifecycle policy, gp3 thay gp2, theo dõi egress/NAT/backup.
  • ✅ Tự động hoá: IaC (CloudFormation/Terraform), runbooks, alarms & dashboards.

Course Content

1) AWS Storage Classes

S3 cung cấp nhiều lớp để cân bằng chi phí ↔ độ trễ ↔ tần suất. Intelligent‑Tiering tự động chuyển đối tượng giữa các tầng; Glacier Instant Retrieval truy xuất mili‑giây cho dữ liệu truy cập vài lần/năm; One Zone‑IA rẻ nhưng rủi ro AZ.

2) Block Storage

EBS cho EC2: gp3 baseline 3.000 IOPS và lên tới 1.000 MiB/s; io2 (kể cả Block Express) cho IOPS ngẫu nhiên cực cao; st1 tối ưu thông lượng tuần tự; sc1 cho dữ liệu lạnh.

3) AWS Database Managed Services

  • RDS/Aurora: relational được quản lý (backup/patch/monitor) — Aurora đạt tới 5× MySQL, tối đa 15 read replicas.
  • DynamoDB: NoSQL key‑value/document, milli‑giây, nhân bản đa AZ; DAX cache đọc microsecond.
  • MemoryDB: tương thích Redis/Valkey, đọc µs, ghi ms một chữ số, bền đa AZ.
  • Redshift: data warehouse quy mô petabyte, MPP, materialized views, Spectrum.
  • Neptune: đồ thị (Gremlin/SPARQL/openCypher); QLDB: sổ cái bất biến (hash‑chaining).

4) AWS Databases — chọn đúng công cụ

OLTP quan hệ → RDS/Aurora; key‑value/document → DynamoDB; đồ thị → Neptune; phân tích BI → Redshift; cache/in‑memory → ElastiCache/MemoryDB; audit ledger → QLDB.

Requirements (để học & lab mượt)

🔒 Bảo mật

KMS keys, IAM least‑privilege, audit CloudTrail, S3 Block Public Access.

📦 Sao lưu

Snapshots, PITR, lifecycle S3, kiểm thử khôi phục định kỳ.

⚙️ Hiệu năng

Read replicas (Aurora/RDS), partition/index, DAX/ElastiCache, cấu hình gp3/io2.

🌐 Khả dụng

Multi‑AZ, health checks, failover, cross‑Region khi cần.

🧮 Chi phí

Chọn lớp S3 phù hợp, tag & Cost Explorer, theo dõi egress/NAT/backup.

🧱 IaC

CloudFormation/Terraform modules, policy checks, pipelines.
